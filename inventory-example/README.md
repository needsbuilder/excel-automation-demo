# 재고 부족 수량 점검 예시

**가상 데이터로 만든 작업 예시이며 실제 고객 자료·납품 실적이 아닙니다.**

재고에서 예약 수량을 빼고, 품목마다 정한 목표 수량과 비교합니다. 입력 7행 중 정상 3행을 계산하고, 예약 초과 1행·중복 품목ID 2행·음수 재고 1행은 확인 대상으로 분리합니다. 부족한 품목은 2개이며 부족 수량 합계는 15개입니다.

| 품목 | 현재 재고 | 예약 | 판매 가능 | 목표 | 부족 |
|---|---:|---:|---:|---:|---:|
| S001 | 18 | 3 | 15 | 10 | 0 |
| S002 | 7 | 2 | 5 | 12 | 7 |
| S003 | 0 | 0 | 0 | 8 | 8 |

Python 3 표준 라이브러리만 사용하며 추가 도구 결제나 설치가 필요하지 않습니다. ZIP을 풀고 해당 폴더에서 실행합니다.

```sh
python3 inventory_check.py input.json my-result.json
python3 -m unittest -v test_inventory.py
```

`input.json`의 수량은 0 이상의 정수입니다. 품목ID는 문자열이며 앞뒤 공백만 제거하고 대소문자는 그대로 구분합니다. 중복 품목은 합산하지 않고 중복된 모든 행을 확인 대상으로 남깁니다. 결과에는 원본 행 번호와 오류 사유가 남습니다. 원본과 기존 결과 파일을 덮어쓰지 않습니다.

S002 재고를 14로 바꾸면 판매 가능 수량은 12, 부족 수량은 0으로 바뀌며 전체 부족 수량은 8입니다. 제공된 `expected-result.json`은 최초 가상 데이터 기준 결과입니다.

현재 재고와 예약 데이터가 정확하다는 전제의 점검 예시입니다. 입고 예정·리드타임·발주 단위·안전재고 예측·실제 구매나 발주 실행은 포함하지 않습니다. JSON 입력을 Python으로 검증했으며 Excel 파일·VBA·Apps Script나 외부 재고 시스템 연동은 검증하지 않았습니다. 실제 업무에는 고객 파일 형식과 재고 기준을 먼저 합의해야 합니다.
